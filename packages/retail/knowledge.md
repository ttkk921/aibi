# BI 业务知识（问数口径）

门店销售看板的业务口径。AI 问数照着这里回答，数字必须和看板一致。数据全是虚构的。

## 通用原则

1. **优先用报表查询**：报表和看板用同一套 SQL 和汇总口径，数字与看板完全一致。只有报表回答不了的维度
   （会员等级、城市、渠道、组别等）才自己写 SQL。
2. **每个回答都写明**：数据日期、筛选条件、用的哪个报表（或 SQL），以及涉及的口径。
3. **金额是「截至当天的当月累计销售额」**：每天一份快照，不同日期之间不能相加；看变化要比较两天的差值。
4. **比率不能直接相加或平均**：汇总时用 `sum(分子)/sum(分母)` 重算——报表查询已经这样做了，自己写 SQL 时也要这样算。
5. 报表结果里 `format=pct` 的值是比例，`0.35` 表示 35%；金额单位是元，回答时可换算成万元。
6. 用户没说日期就用最新日期，并说明「截至 YYYY-MM-DD」。不知道就说不知道，不要编造字段或数据。

## 报表

公共维度：日期、品类、品类大类、大区（门店明细和导购表还有门店 / 导购）。
品类来自品类对照表（`bi_category_map`）：原始品类 → 标准品类、品类大类。

| 报表 id | 标题 | 口径要点 |
|---|---|---|
| `store-overview` | 大盘销售 | 目标销售额来自门店月度目标；`序时目标金额` = 目标销售额 × 序时进度；`累计达成率` = 销售额 / 目标销售额；`序时达成率` = 销售额 / 序时目标金额；`序时缺口` = 序时目标金额 − 销售额（负数表示超序时进度）；`同期销售额环比` = 销售额 / 上月同期 − 1 |
| `store-detail` | 门店明细 | 加人力（按品类分摊）、人均类、新客/老客拆分；`大区平均达成率` 是同一 日期 + 品类 + 大区 的 销售额合计 / 目标合计；`是否超过大区平均` 用门店达成率和它比 |
| `staff` | 导购表 | 口径同门店明细，拆到导购；目标只到门店，所以没有个人目标；`门店平均销售额` = 同一 日期 + 品类 + 门店 的销售额合计 / 导购数 |
| `ranking` | 门店排名 | 只排有目标的门店；`达成率排名` 是「名次/门店数」；`距离前一名差距` = (前一名达成率 − 本店达成率) × 本店目标销售额，即追上他还需多做多少销售额；`距离目标差额` = 目标销售额 − 销售额 |
| `store-summary` | 门店汇总 | 由门店明细按门店 / 大区汇总；比率一律 sum/sum 重算，达成率不是把各门店的达成率平均 |

## 关键口径（务必遵守）

- **达成率只统计有目标的部分**：没有目标的门店 × 品类没有达成率，但仍计入销售额；汇总时用
  `sum(销售额) / sum(目标销售额)`，目标为空的行不进分母。
- **差额、缺口 = 目标 − 销售额**，正数表示还差多少。
- **大区平均达成率不能跨大区汇总**：按大区汇总时它没有意义（为空）。
- **客群只分三档**：散客（非会员）、新客（首购在 3 个月内）、老客。

## 数据表（写 SQL 用）

| 表 | 内容 | 粒度 / 更新 |
|---|---|---|
| `bi_store_daily` | 销售**日汇总**（导入明细时自动生成，报表优先用它） | 日期 × 大区 × 城市 × 门店 × 导购 × 品类 × 渠道 × 客群 |
| `bi_sales_detail` | 销售明细（会员号、订单金额原文等只有它有） | 日期，每天一份 |
| `bi_category_map` | 品类对照表：原始品类 → 标准品类、品类大类 | 维表，整表覆盖 |
| `bi_store_target` | 门店月度目标：月 × 门店 × 品类 → 目标销售额 | 每月 |
| `bi_timeline_target` | 序时目标：日期 × 品类 → 当天应完成的进度 | 每月 |
| `bi_store_headcount` | 门店人力：月 × 门店 × 品类（一个导购卖几个品类就按比例摊开，相加 = 门店总人力） | 每月 |
| `bi_margin_rate` | 毛利率表：标准品类 → 毛利率（毛利额由它算出来） | 维表，整表覆盖 |
| `bi_member_profile` | 会员表：会员号 → 首购月、等级（客群由它算出来） | 维表，整表覆盖 |
| `bi_store_staff` | 人员表：工号 → 姓名、大区、门店、组别 | 维表，整表覆盖 |

写 SQL 的要点：

- 按门店、按导购统计优先用汇总表，订单数用 `sum(orders)`；只有汇总表没有的字段（会员号、城市、渠道）才查明细表。
- 明细表**一定要带日期条件**；查询账号看不到会员号（`member_no`），明细表**不能 `select *`**。
- 日期列是 `date` 类型，用 `sale_date = '2026-01-05'`，不要用 `like`。
- 品类要过对照表：`left join bi_category_map cm on cm.raw_category = d.category`，
  标准品类 = `ifnull(cm.category, d.category)`，品类大类 = `ifnull(cm.category_group, d.category)`。
- 目标和人力都只到月，人力还分品类；关联前先把明细聚合到同样的粒度（日期 × 门店 × 品类），否则金额会被放大。

## 示例问题与回答要点

下面只示范怎么查、答案包含什么；X、Y 是占位，**实际数字一律以本次查询结果为准**。

| 问题 | 怎么查 | 回答要点 |
|---|---|---|
| 今天销售额和累计达成率是多少？ | `store-overview`，不分组，看合计 | 销售额、累计达成率、序时达成率、序时缺口（负数说明已超序时进度） |
| 哪个品类的序时缺口最大？ | `store-overview`，按品类分组，按序时缺口倒序 | 品类及序时缺口、序时达成率，再给整体作对比 |
| 累计达成率最低的三个门店？ | `store-detail`，按门店分组，按累计达成率排序 | 三个门店及各自达成率、销售额、目标，再给合计作对比 |
| 人均销售额最高的门店？ | `store-detail`，按门店分组，按人均销售额倒序 | 门店、人均销售额（附人力和销售额），再给整体人均作对比 |
| 哪个门店离前一名还差多少销售额？ | `ranking`，筛门店或大区 | 前一名门店、本店达成率差多少、按本店目标要追上需多做多少销售额 |
| 哪个导购的新客占比最高？ | `staff`，按导购分组的 SQL（或 `bi_store_daily`） | 导购、新客销售额、新客占比，并说明散客不算新客 |
